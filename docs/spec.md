# musicdl-web 规格

## 目标

musicdl-web 是仅供一名操作者使用的桌面端私有 Web 工具。它在网易云音乐与 QQ 音乐中搜索平台歌曲，提供短试听确认，按当前平台会话动态列出可获取音质，并将操作者明确选择的音频保存到 Navidrome 可扫描的服务器音乐库，或通过浏览器逐文件取回。

## 一期范围

- 网易云音乐与 QQ 音乐同时作为首批音乐源。
- 一个自由文本搜索框接受歌名、歌手名或二者组合。
- 来源范围可以是全部、网易云或 QQ；全部来源时按平台形成两个独立结果组，首批各 20 条并分别加载更多。
- 同一内容在两个平台中始终是两个独立的平台歌曲，不自动合并或去重。
- 支持单选与跨结果组多选；批量中的每首歌形成独立下载任务。
- 支持由平台在当前会话下合法提供的短试听片段，一次只试听一首。
- 不解析歌单 URL，不下载整张专辑或歌手全部作品，不提供整首播放、播放列表、收藏或播放历史。

## 平台会话

- 搜索和公开获取不要求登录。
- 需要使用操作者自身账号权益时，可以建立网易云或 QQ 平台会话。
- 实验性扫码登录依赖非公开 Web 行为，公开 Compose 默认关闭，NAS 部署显式开启；手动导入既有 Cookie 始终作为兜底。
- 系统永不接收平台账号密码，不伪造 IP，不规避验证码或风控。
- 平台会话以认证加密形式保存在独立持久卷中，密钥由 Compose secret 注入；会话、Cookie、token、二维码内容和来源 URL不得进入日志、URL、浏览器持久化或 API 响应。
- 会话跨容器重启保留，支持有效性检测、QQ 可用刷新材料的受控刷新，以及替换、退出和清除。

## 搜索、试听与音质

- 搜索先返回平台歌曲元数据，不在搜索阶段解析下载 URL。
- 音质按歌曲、平台会话和时点动态解析；只有进入可见区域或被选中的歌曲才异步解析，结果短暂缓存。
- 下载前重新验证所选音质，只请求该平台原生档位；响应档位不一致、会话变化或选项过期时明确失败，不自动降级。
- 普通立体声音频按“标准有损 < 高品质有损 < 无损 < Hi-Res < 母带”比较；杜比、全景声和沉浸声是替代版本，不参与升级排序。
- 短试听由后端代理平台合法提供的试听资源，不暴露平台 URL、不持久缓存；无可用试听时显示“不可试听”。

## 下载、去重与升级

- 下载任务由平台歌曲、精确音质和文件交付方式共同确定。
- 服务器音乐库中，每个平台歌曲只保留一个当前受管版本；网易云与 QQ 版本互不覆盖。
- 搜索结果显示“已入库”和当前音质；相同或更低音质不再创建服务器保存任务。
- 只有出现更高保真等级时才提供显式升级；新版本完整下载、校验和写标签后原子替换旧版本。
- 下载批次允许部分成功，一首失败不影响其他任务；失败项可以单独重试。

## 文件交付

### 保存到服务器

这是默认交付方式。完整产物写入 Docker 挂载的 `/music`，并在容器重建后保留。

目录约定：

```text
/music/{专辑艺术家}/{专辑} ({年份})/{碟号-曲号} - {歌名}.{扩展名}
/music/{歌手}/Singles/{歌名}.{扩展名}
```

缺失的年份、碟号或曲号直接省略；规范化路径冲突时才追加 `[netease-ID]` 或 `[qq-ID]`。

入库产物保留平台原始音频编码而不转码，并尽力写入 `TITLE`、`ARTIST`、`ALBUM`、`ALBUMARTIST`、曲号、碟号与日期，嵌入封面，同时保存专辑 `cover.jpg` 与音频同名 `.lrc`。音频、标签和 sidecar 全部完成并校验后才对 Navidrome 原子可见。

### 浏览器取回

后端在临时工作区生成产物，浏览器逐文件取回，产物不进入服务器音乐库。批量操作不生成 ZIP；“下载全部”逐个触发成功文件，浏览器阻止多文件下载时保留逐首取回入口。交付或过期后清理临时产物。

## Navidrome 边界

- Navidrome 已独立运行，本项目不捆绑、不配置、不重启、不调用或管理它。
- 本项目读写宿主 `/data/media/music`；Navidrome 继续只读挂载同一目录，并依靠现有 watcher 与 `ND_SCANSCHEDULE=1h` 发现成品。
- Navidrome 完全以媒体标签组织曲库；路径只用于人工浏览。
- musicdl-web 不提供删除、移动、重命名、标签编辑或全库整理。
- 只有入库索引登记的受管产物可以被音质升级替换；未登记文件永不修改或删除。
- 登记文件在原路径缺失时标记“文件缺失”并允许重新下载，不自动重建、不猜测新位置、不扫描全库。

## 下载队列与状态

- 状态依次为：排队、解析音质、下载、写标签、入库，以及完成、失败或已取消终态。
- SQLite 持久化队列、任务历史、入库索引和应用状态。
- 默认最多并发 2 首，可由环境变量调整。
- 支持取消排队或进行中的任务、单独重试失败任务，并在容器重启后安全恢复未完成任务。
- 终态历史可以清除；清除只删除历史与过期临时产物，不删除音乐库文件。入库索引长期保留。

## 工作台

- 单页、桌面端、简体中文，跟随系统浅色或深色主题。
- 顶部：网易云与 QQ 会话状态、实验性扫码与会话导入入口。
- 中部：搜索、来源范围、两个来源结果组、试听、逐歌曲音质、跨组批量操作。
- 侧栏或底部：队列阶段、进度、错误、取消、重试和任务历史。
- 使用紧凑表格、小尺寸封面和明确状态；不做移动端适配、播放器式大封面、频谱或复杂动画。

## 应用架构

- 前端：Vue 3、TypeScript、Vite。
- 后端：Python 3.12、FastAPI。
- 状态：SQLite。
- 单一生产容器提供 API、编译后的前端静态资源和有界后台下载执行器，对外监听 4534。
- 应用无本地账号或访问密码；内网、VPN、防火墙和反向代理由部署环境负责，文档明确禁止直接暴露到不受信任网络。

### 平台与 musicdl 边界

- 自有 `NeteaseAdapter` 和 `QQAdapter` 负责平台自有域名上的搜索、元数据、会话绑定能力快照和精确单档解析。
- 自有下载器负责重新解析、域名与重定向白名单、流式下载、完整性与媒体一致性校验。
- 自有媒体发布器负责标签、封面、歌词与原子入库。
- `musicdl==2.13.4` 仅可出现在 `MusicdlCompatV2134` 中，最多复用经验证无网络副作用的加密或签名原语。
- 禁止实例化上游具体音乐客户端、调用其公开 `search()` / `download()`、调用第三方解析路径，或让上游 `SongInfo` / `raw_data` 穿过兼容层。
- 若 spike 证明没有值得安全复用的原语，则删除 `musicdl` 依赖并停止相关兼容层表述。

## 许可与发布

- 自有代码使用 Apache-2.0。
- `musicdl` 的 PolyForm Noncommercial 1.0.0、Required Notice 和免责声明单独保留；完整应用明确限定个人非商业用途。
- 不暗示与网易云音乐、QQ 音乐或 Navidrome 存在官方合作或授权。
- 当前 `musicdl/` 检出仅作本地参考，必须排除在版本控制、构建上下文和发布产物之外。
- 公开发布源码、lockfile 和 Dockerfile，不发布预装 `musicdl` 的公共镜像。

## NAS 部署

```text
服务目录       /data/docker/musicdl-web
端口           4534:4534
运行用户       1000:1000
应用数据       /data/docker/musicdl-web/data:/data
临时文件       /data/docker/musicdl-web/tmp:/tmp/musicdl
会话密钥       /data/docker/musicdl-web/secrets/session.key:/run/secrets/session.key:ro
音乐库         /data/media/music:/music
时区           Asia/Shanghai
重启策略       unless-stopped
日志轮转       10m × 3
```

Y9000P 与 NAS 均为 `linux/amd64`。发布时在 Y9000P 构建固定版本镜像，导出并校验后传入 NAS，NAS 执行 `docker load` 与本项目 `docker compose up -d`；不修改 Navidrome Compose，也不在 NAS 编译源码。

## 开发准入门槛

完整产品开发前，网易云与 QQ 各以匿名可获取歌曲和操作者账号有权益歌曲完成纵向 spike。每个平台必须证明：搜索不预解析下载 URL、逐档选项真实、精确下载不降级、无第三方域名、无共享 Cookie、TLS 不降级、媒体完整且 Navidrome 产物正确。任一平台失败即停止该平台正式开发并报告证据，不增加绕过 fallback。
